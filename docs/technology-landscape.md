# Winding software: technology landscape

Research date: November 18, 2026. Desk research from vendor pages, community forums, documentation and open-source repositories. Nothing here was tested on a machine, and vendor capabilities should be reconfirmed before making commercial comparisons. Items marked *inferred* are conclusions drawn from the sources rather than statements found in them.

This note covers what existing tools do and how, not their pricing or positioning. It ends with the decisions it led to in Filar (the planner in this repository).

## X-Winder

### Machine and controller

- Two models: 2-axis (mandrel rotation, carriage) and 4-axis (adds a cross-feed and a rotating delivery head). [Product page](https://xwinder.com/), [3DPrint.com overview](https://3dprint.com/53440/x-winder-filament-winder/).
- Published limits: mandrel 90 RPM, carriage 8 in/s. [4X-23 page](https://xwinder.com/4-axis-model-4x-23/).
- Each axis has its own USB controller box; the replacement board is listed as a Phidgets 1067 stepper controller. [Axis controller board](https://xwinder.com/axis-controller-ic-board/).
- *Inferred:* there is no G-code firmware on the machine. The Windows "Executor" program interprets the file and drives each board over USB. This fits the recurring "detached stepper" and USB-hub threads on the community forum.
- Software is Windows only, and documentation is mostly video. [Raspberry Pi thread](https://community.xwinder.com/blog/xwinder-on-raspberry-pi).

### Designer workflow

- Inputs visible in a generated file header: left and right diameter, total length, filament width and thickness, units.
- In 4-axis mode the wind angle is not a free input. The vendor describes it as "a dependent variable": the user picks from a list of achievable angles per layer. [Pattern generation thread](https://community.xwinder.com/blog/problem-with-pattern-generation-using-x-winder-designer).
- Layer types are helical and hoop; moving between them needs manual intervention.

### File format

A real 4-axis file generated by Designer v419 is attached to [this forum post](https://community.xwinder.com/blog/x-winder-working-differently-every-time-executed). Representative lines:

```
G20 [Units are Inches]
G90 [Absolute Positioning]
M601 [MARK THE MANDREL REFERFENCE ANGLE]
G1 F6,00 Z16,00 S8,75 C21,87 A69,98  [MOVE LEFT END]
G2 K40,00 F0,91 Z18,50 E4,15 Y-1,00 R4,31 B45,29 U1,65 V2,50 H16,00 W-1,00 S12,00 C150,00 A219,98 [CW ELLIPSE AT LEFT END]
G5 K2,00 F2,20 Z16,00 E1,45 Y0,65 R21,27 B-75,86 ... [DH G5 WITHDRAWL LEFT END]
```

Decoded against the numbers in that file (*inferred* unless the file's own comments say so):

| Word | Meaning |
| --- | --- |
| Z | Carriage position, absolute |
| F | Carriage speed in units per **second** |
| S | Mandrel RPM |
| C | Mandrel rotation during the block, incremental degrees |
| A | Cumulative mandrel angle since M601 |
| Y, B | Delivery-head cross-feed position and rotation |
| H, W, V, U | Centre and semi-axes of the turnaround ellipse |
| K, E, R | Not established |

G2 and G3 are redefined as quarter-ellipse turnarounds, G5 and G6 as head withdrawals. Brackets are comments. The sample uses decimal commas, a locale bug users have had to patch around.

The vendor states that the machine "only understands X-Winder G-Code or modifications thereto" and that CADWIND output will not run. [Support thread](https://community.xwinder.com/blog/cadwind-xwinder).

**Implication:** X-Winder output is a separate post-processor, not a variation on standard G-code, and it can only be validated on a real machine.

### Reported limitations

- Stalls at the turnaround commands, often on Windows 11. [Thread 1](https://community.xwinder.com/blog/4-axis-winding-mode-stuck-at-the-hemi-ends), [thread 2](https://community.xwinder.com/blog/executor-stuck-at-g2-command).
- "The software deals with either constant diameter or constant taper"; stepped parts need hand-spliced code. [Variable diameters](https://community.xwinder.com/blog/varible-diameters).
- Users report significant errors on cones and nose cones. [Nose cone thread](https://community.xwinder.com/blog/nose-cone-winding-1).
- No direct wind-angle entry in 4-axis mode, no friction parameter, and variable wall thickness only by hand-editing. [Variable wall thickness](https://community.xwinder.com/blog/variable-wall-thickness).

These are forum reports from 2019 to 2023; how common they are today is unknown.

## Open-source planners

| Project | Stack and licence | Shapes | Planning | G-code | Preview |
| --- | --- | --- | --- | --- | --- |
| [Cyclone](https://github.com/reilleya/cyclone) | TypeScript CLI, GPLv3 | Cylinder | Constant-angle helical and hoop, fixed dwell at the ends | Marlin on a printer board: X carriage, Y mandrel, Z head rotation | None |
| [FiberPath](https://github.com/CameronBrooks11/fiberpath) | Python core, Tauri + Svelte GUI, AGPL-3.0 | Cylinder, reducing cone, nose cone | Closed-form on cylinder and cone; optional friction term capped by a slip limit | Marlin with real rotary axes: X, A, B | Time estimate and 2D unwrapped plot |
| [Astra-Bremen Winding_Machine](https://github.com/Astra-Bremen/Winding_Machine) | Python/Tkinter | Tank with end caps | Helical by angle and pattern number, hoop | Klipper; `G92 A0` after every cycle | Pseudo-3D |

Details worth knowing:

- Cyclone and FiberPath compute circuits as `ceil(π·D·cos α / band width)` and require that count to be divisible by the pattern number. [FiberPath planner maths](https://fiberpath.org/fiberpath/reference/planner-math/).
- FiberPath rejects hoop layers on cones and anchors the cone angle at the large end. [Wind format guide](https://fiberpath.org/fiberpath/guides/wind-format/).
- No open-source tool found offers a pattern-selection table, thickness build-up, or a 3D machine simulation. No Rust planner was found.

## Commercial packages

- **CADWIND** (MATERIAL): friction factor as an input, an automatic list of possible patterns, per-point thickness, 3D machine animation with range check; FEA export and more than four axes are paid extensions. [Features](https://www.material.be/cadwind/features/), [packages](https://www.material.be/cadwind/compare-packages/).
- **Cadfil**: a pattern dialog listing options by band pattern and deviation; dwell winding as the alternative to stretching the path; a layer table with coverage, circuits, pattern, dwell, time, waste length and cumulative thickness. [Pattern options](https://www.cadfil.com/help/html/cadh033o.htm), [dwell](https://www.cadfil.com/help/html/cadh0uef.htm), [pipe layer table](https://www.cadfil.com/help/html/cadh_multipipe.htm).
- **ComposicaD**, **TaniqWind Pro**, **Mikrosam Winding Expert**: similar cores, with robots, collision checking and FEA export as upper tiers. [ComposicaD](https://www.composicad.com/), [TaniqWind](https://composites.taniq.com/filament-winding-software).

*Inferred* split:

- **Expected everywhere:** parametric tube and cone mandrels, hoop and helical layers, a list of closed patterns, friction-limited turnarounds, a layer table with thickness, a 3D fibre preview, 2 to 4 axis output with a configurable post-processor.
- **Premium:** non-axisymmetric parts, 5 or 6 axes and robots, collision checking, FEA export.

## Process rules that software has to encode

- **Winding angle** is measured from the mandrel axis: 0° axial, 90° hoop.
- **Circuits for full coverage:** `ceil(π·D·cos α / band width)`.
- **Closing a pattern:** either stretch the path slightly or add hoop dwell at the ends. Dwell leaves the angle alone but thickens the ends. Cadfil advises keeping path stretch within about ±5%.
- **Turnarounds on an open tube:** a friction-limited turn to 90°. On a cylinder its length is `(R/μ)(1/sin α − 1)`, so low angles need long run-outs. Cadfil advises 40° to 90° for plain pipe, and pins or end caps below about 30°. [Pin rings](https://www.cadfil.com/help/html/pin-plunge-pipewinding.html).
- **Friction coefficient:** Cadfil quotes 0.1 to 0.2 as typical. No verified figure was found for towpreg.
- **Cones:** geodesics obey Clairaut's relation, `r·sin α = constant`, so the angle rises towards the small end. Holding a constant angle needs friction; Cadfil limits it to tapers under about 1:20. [Tapered pipes](https://www.cadfil.com/help/html/tapered_pipes.htm).
- **Thickness on a taper** grows towards the small end, roughly as `1/(r·cos α)`.

## DIY controller conventions

| Firmware | Seen in | Axis words | Note |
| --- | --- | --- | --- |
| Marlin (stock) | Cyclone | X carriage, Y mandrel, Z head | Rotary axes configured as linear, steps per unit set to steps per degree |
| Marlin 2.0.9+ | FiberPath | X, A, B | Real rotational axes |
| Klipper | Astra-Bremen | X, Y, A | Mandrel angle reset with G92 each cycle |
| RepRapFirmware | X-Winder retrofit on a Duet | X, Y, A, B | [Forum post](https://forum.duet3d.com/post/288167) |
| LinuxCNC, grblHAL | General | X plus A/B | G93 inverse-time feed available. [LinuxCNC feed rules](https://linuxcnc.org/docs/html/gcode/machining-center.html), [grblHAL](https://github.com/grblHAL/core) |

Feed rate is the trap. Under the LinuxCNC rule, which Marlin's documentation says it follows, `F` applies to the linear axes whenever one is moving, so the mandrel speed is implied. With rotary axes disguised as linear ones, `F` is the combined rate over millimetres and degrees. Inverse time (G93) avoids the ambiguity where the controller supports it.

## What Filar does as a result

| Finding | Decision |
| --- | --- |
| X-Winder users cannot enter a wind angle or friction value, and cones are a weak spot | Angle is a direct input; friction is a parameter; cones are supported in constant-angle and geodesic modes, with the friction demand reported |
| Commercial tools all offer a list of closed patterns; open-source tools do not | Every helical layer shows a table of closed patterns with pattern number, circuits, coverage and dwell |
| Patterns are closed by path stretch or by dwell | Dwell, split between the two ends, so the specified angle is always what is wound |
| Low-angle turnarounds need long run-outs or pins | Friction-limited turnarounds are computed and checked against the mandrel length; a pin-ring mode is available |
| DIY machines differ in axis words, units and feed semantics | Machine profiles set axis words, scale, direction, limits, feed mode and spindle wrap; presets follow the Cyclone, FiberPath, grblHAL and LinuxCNC conventions |
| X-Winder's file format is its own dialect | Not attempted yet; it needs a dedicated post-processor and a machine to test on |
| No open-source tool simulates the machine in 3D | Simulation and export run from the same samples, so the preview is the program |
